# Веб-интерфейс Dozor

Интерфейс встроен в бинарник (`//go:embed web/*` в `internal/dozor/http.go`) и работает на ванильных HTML, CSS и JS: без фреймворка, сборки и CDN. Для HLS локально включён hls.js 1.7.3. Единственное исключение — меню: это настоящий общий компонент Sidebar из `@jourloy/00`, собранный в закоммиченные `vendor/a00-menu.{js,css}` (раздел «Меню: общий компонент 00»). Установка npm-пакетов нужна только для пересборки меню (`make menu`); для сборки и запуска Dozor она не нужна. Оформление следует дизайн-системе «00 — Atmosphere» в **тёмной теме**.

## Источник и принципы

- Дизайн-система: `docs/design/00.md` репозитория `monorepo-frontend`, код компонентов — `packages/00/src`, коммит монорепозитория **e405f620**.
- 00 официально светлая (§3.5). Тёмная карта токенов — собственное решение продукта: цвета ниже подобраны под правила контраста §3.5 и проверены скриптом.
- Компоненты не импортируются, а портируются: CSS-значения (высоты 48/54/40/32, радиусы, hover-подъём 2 px за 320 мс, фокус 2 px offset 4 px, switch 44×26, слайдер 6/20 px и т. д.) сохранены, разметка React заменена нативными элементами. У каждого блока в `components.css` в комментарии указан исходный файл. Исключение — навигация: меню импортируется как есть (раздел «Меню: общий компонент 00»).
- Рабочие экраны «тихие» (§2, §13): без световых пятен, сеток, орбит и наклона. Ни одного надзаголовка (§5.4), ни одной точки в конце заголовка. Убраны декоративные подделки: CSS-радар, зелёная точка «В домашней сети», слоган в подвале.
- Сервер отдаёт строгий CSP (`script-src 'self'; style-src 'self'`): в HTML нет инлайновых скриптов, `<style>`, `style="..."` и обработчиков `onclick`; динамические значения идут через CSSOM (`el.style.setProperty`). Шрифты — файлы того же origin (data: запрещён).

## Материал карточек

Все карточки — **paper** (§7.1, §12): заливка `surface`, рамка 1 px `border`, радиус `--a00-radius-card` (md, 12 px), мягкая двойная тень от `--a00-tint-rgb` и верхняя кромка `--a00-paper-edge`. Карточек-ссылок нет, поэтому подъёма при наведении нет. Отступ 28 px, на ≤ 1000 px — 24 px. Альфа теней увеличена вчетверо относительно светлой темы (0,1 и 0,3 вместо 0,027 и 0,075), иначе на тёмной основе тень не читается. По той же причине кольцо вокруг бегунка слайдера при перетаскивании берётся от `ink` (16 %), а не от чёрного `tint`: чёрное кольцо на тёмной основе не видно. `<html data-a00-card-material="paper">` оставлен для соответствия 00.

## Меню: общий компонент 00

Навигация — единственное место, где компонент 00 не портирован, а импортирован: `SidebarShell` (с `SidebarDock` для рейки и `SidebarMobileNav` для нижней панели) и тему `SidebarDarkTheme` из `@jourloy/00` рисует настоящая реализация. Меню совпадает с остальными приложениями монорепозитория и обновляется вместе с пакетом. Пакет — исходники TS/React под Next, поэтому для ванильного фронтенда он собирается esbuild в закоммиченные `web/vendor/a00-menu.js` и `a00-menu.css` (как hls.js): `go build` и релизный скрипт Node не требуют. Остальной интерфейс по-прежнему портирован.

**Пересборка**: `make menu` (`npm --prefix assets-src/menu ci`, затем `node assets-src/menu/build.mjs`; нужен Node 20.9+). Каталог пакета задаёт `A00_DIR` (по умолчанию `../monorepo-frontend/packages/00` рядом с репозиторием), пакет только читается. Обычные `make build`, `make test` и `make check` бандл не пересобирают; `make check` проверяет его синтаксис (`node --check`).

**Привязка к версии**: первая строка обоих файлов — баннер с коммитом монорепозитория, числом и хешем файлов `packages/00`, которые вошли в бандл (хеш однозначно задаёт содержимое, даже когда дерево грязное), и версией React. Суффикс `-dirty` ставится, только если один из этих файлов отличается от коммита или не отслеживается; правки в других местах `packages/00` на него не влияют. На момент сборки: **d36c566f**, 7 файлов, React 19.2.6. Сборка детерминирована: без дат, повторный запуск и сборка через симлинк на `A00_DIR` дают те же байты. Лицензии вошедших пакетов (React, lucide-react, tailwind-merge, clsx, Tailwind) — `vendor/a00-menu-LICENSES.txt`, релизный скрипт кладёт их в `LICENSES/a00-menu.txt`.

**Что собирается**

- `@jourloy/00/...` разрешается по `exports` пакета из `A00_DIR` (без `file:`-зависимости). Остальные импорты пакета (`react`, `clsx`, `tailwind-merge`, `lucide-react`) берутся только из `assets-src/menu/node_modules` версиями из `package-lock.json`: они совпадают с `packages/00/package.json`. `A00_DIR` приводится к реальному пути, а после сборки скрипт проверяет по `metafile`, что каждый npm-пакет (и `react` в первую очередь) вошёл ровно из одного каталога и что файлы `packages/00` вообще вошли; иначе сборка падает и в `vendor/` ничего не пишет. Ещё одна проверка сборки: каждая подпись из `defaultSidebarLabels` пакета должна быть в списке `SIDEBAR_LABEL_KEYS` файла `src/index.tsx`.
- `next/link` заменён заглушкой `src/stubs/next-link.tsx`: Sidebar импортирует его только как значение `linkComponent` по умолчанию, меню передаёт обычный `<a>`. Любой другой `next/*` ломает сборку. Next в бандл не входит.
- Разметка Sidebar опирается на утилиты Tailwind (контракт пакета: хост сканирует `packages/00/src`), поэтому Tailwind CLI генерирует ровно утилиты трёх компонентов Sidebar, без preflight. CSS Modules темы собирает esbuild (`local-css`, имена `sidebar_dark_*`). Шрифты и токены `--a00-*` в бандл не входят: их берёт страница (`tokens.css`, `fonts/`). Поправки хоста лежат в `assets-src/menu/src/host.css` (без слоя, поэтому перекрывают и тему, и утилиты).
- Иконки остаются спрайтом страницы: каждая — крошечный компонент `<svg class="ui-icon"><use href="#i-…"/></svg>`.

**Контракт с `app.js`**: бандл не запускается сам, а выставляет `window.DozorMenu.mount(el, options)`. `app.js` вызывает его один раз при старте: `items` (`hash`, `label`, `icon` — id спрайта без `i-`; первый пункт домашний), `labels` (все шесть подписей Sidebar: `collapse`, `pin`, `navigation` — подпись ориентира «Разделы», `brandTitle`, `brandSigil`, `brandAriaLabel`; `mount` бросает ошибку, если одной нет, чтобы смена значений по умолчанию в пакете не меняла русский текст), `logoutLabel`, `onLogout` (общий обработчик выхода, тот же, что у кнопки верхней панели). Возвращает `update({version})` (версия под названием приходит позже, со статусом) и `unmount()`. Активный пункт бандл определяет по `location.hash` и обновляется по `hashchange`; неизвестный хэш считает первым пунктом, как и маршрутизатор. Заголовки, остановка видео и плеера, загрузка событий остаются в `app.js`. Меню лежит внутри `#shell`, поэтому видно только на экране оболочки. Приложение работает и без меню: если `/vendor/a00-menu.js` не загрузился, `app.js` пишет `console.error`, ставит `data-menu="missing"` на `#shell` и продолжает запуск; тогда верхняя панель с «Выйти» остаётся и от 1024 px, а отступ под рейку не добавляется.

**CSP не менялся**: в бандле нет `eval` и `new Function`, он не создаёт `<style>` и не вставляет правил (React вставляет `<style>` только для элементов `<style precedence>`, их в дереве нет); стили через CSSOM (`element.style`) политика разрешает. Подключение — файлами того же origin: `<link href="/vendor/a00-menu.css">` и `<script defer src="/vendor/a00-menu.js">` перед `app.js`. После смены пакета проверять: `grep -c 'eval(\|new Function' internal/dozor/web/vendor/a00-menu.js` должен дать 0.

**Отличия от прежнего меню** (это поведение компонента):

- Рейка от 1024 px раскрывается по наведению и фокусу (4,75rem → 16,5rem) и закрепляется кнопкой; кнопка раскрытия стоит на месте логотипа. Хост держит рейку `position: fixed`: раскрытие по наведению накрывает страницу, не сдвигая её, и только закреплённая рейка освобождает место (`app.css`, `:has([data-dock-pinned="true"])`). Закрепление сохраняется между разделами.
- Рейка и нижняя панель — скруглённые (22 px) плавающие панели темы, нижняя панель не полноширинная. Её высота 69 px плюс отступ 12 px, поэтому тосты подняты с 88 до 96 px (`--a00-toast-bottom`), а `scroll-padding-block-end` ниже 1024 px равен 96 px плюс safe-area, чтобы поле в фокусе не оказалось под панелью. Нижняя панель показывает не больше пяти пунктов (ограничение компонента); у Dozor их ровно пять.
- Граница 1024 px задана в px и у рейки (`host.css`), и у нижней панели, и у страницы: утилита `lg:flex` Tailwind измеряется в `rem` (64rem) и зависела бы от размера шрифта браузера, поэтому видимость рейки хост задаёт сам. На любой ширине и при любом размере шрифта показана ровно одна из двух панелей. На низком окне (меньше ~440 px по высоте) рейка прокручивается внутри себя.
- Ориентир рейки — `<aside aria-label="Разделы">` (complementary), нижней панели — `<nav aria-label="Разделы">`: так размечен компонент; одновременно виден только один из них.
- Версия показана под названием в раскрытой рейке («v1.0.1», без повтора слова Dozor). «Выйти» — кнопка в подвале рейки; на телефоне выход остаётся в верхней панели, копию над нижней панелью хост скрывает.
- Наведение на пункт рейки не сдвигает его (Tailwind v4 двигает через `translate`, хост его отменяет) и красит плитку тоном `surface`, тише плитки текущего пункта.
- Разделителей между пунктами нет (слот `divider` пустой): рабочие экраны «тихие». Верхняя панель на телефоне остаётся (бренд и выход), от 1024 px она скрыта, как и раньше.

## Шрифты и лицензии

Geist (текст), Cormorant Garamond (акцентные заголовки не мельче 24 px), IBM Plex Mono (RTSP-адреса, UUID, JSON масок; только latin 400 и 500, около 20 КиБ). Inter и Roboto не нужны. Имена семейств — как в 00: «A00 Geist», «A00 Cormorant Garamond» (с метрическим запасным «A00 Cormorant Garamond Fallback»), «A00 IBM Plex Mono»; `font-display: swap`.

Лицензия SIL OFL: тексты лежат рядом со шрифтами — `web/fonts/Geist-OFL.txt`, `CormorantGaramond-OFL.txt`, `IBMPlexMono-OFL.txt`. Папка `web/` вшита в бинарник, поэтому тексты попадают в релизный бинарник и доступны по `/fonts/*-OFL.txt`. `scripts/collect-licenses.py` собирает уведомления только Go-модулей и не менялся; отдельно в `LICENSES/` архива шрифты не копируются.

## Браузеры

Нужны современные браузеры: интерфейс опирается на `@layer`, `:has()`, нативный `<dialog>`, container queries и `Intl` (Chrome и Edge 111+, Firefox 121+ из-за `:has()`, Safari 16.4+); `subgrid` у карточек камер — необязательное улучшение, без него работает запасная раскладка. Без JavaScript показывается только экран «Загрузка» с пояснением; сама работа без JS невозможна (как и в прежней версии).

## Экраны и поведение

- **Маршруты по хэшу**: `#overview`, `#live`, `#events`, `#cameras`, `#settings`; перезагрузка сохраняет вкладку, «Назад» работает. Пункты меню с `aria-current="page"`. Хэш не совпадает с `id` секций (`tab-…`), чтобы браузер не прокручивал страницу.
- **Онлайн**: выбор включённой камеры, видео со звуком (по умолчанию выключен), «Переподключить» и «К эфиру». Состояния подключения, просмотра, паузы и ошибки; повтор после обрыва с задержкой до 10 секунд, таймаут ожидания изображения 20 секунд. На смене камеры, уходе из раздела, скрытии вкладки и выходе из аккаунта запросы отменяются и плеер уничтожается. Возврат возобновляет текущую трансляцию. Без камер или диска — пояснение и ссылка в соответствующий раздел. MSE-браузеры используют hls.js с отключённым worker; при отсутствии MSE используется нативный HLS, поэтому CSP разрешает `blob:` только в `media-src`. Плейлисты и сегменты проходят авторизацию Dozor. Кнопки «Онлайн» есть в обзоре и карточках камер.
- **Оболочка**: от 1024 px левая рейка общего меню (4,75rem с иконками, раскрывается до 16,5rem по наведению и фокусу, закрепляется кнопкой; бренд, версия под ним и «Выйти» в подвале); ниже — компактная верхняя панель высотой 57 px (токен `--topbar-height`; бренд с зоной нажатия 44 px, иконка выхода с `aria-label`) и нижняя панель из пяти пунктов с учётом safe-area. Надпись «Dozor» в верхней панели — Geist 600 22 px (навигация по 00.md §5.1 набрана в Geist, Cormorant остаётся акцентным заголовкам); на экране входа отдельной строки с названием над формой нет (§5.4). Ниже 1024 px `scroll-padding` сверху равен высоте панели плюс 24 px, чтобы прокрутка и фокус не оказывались под ней. Основная колонка до 1280 px, поля `clamp(24px, 4vw, 56px)`, на ≤ 640 px — 20 px. Скип-ссылка не меняет хэш.
- **Обзор**: одна карточка «Сводка» разного веса вместо трёх одинаковых метрик (§10.2, §17): главный результат «Камеры в сети» крупно (Geist 600 до 56 px) и короткий список «Занято на диске» (с шкалой) и «Очередь S3»; один стикер на карточку. Под ней «Состояние камер» и «Журнал».
- **Сетки карточек**: карточки одного ряда равны по высоте (§6, §18.3): сетка не задаёт `align-items`, поэтому ряд растягивается. У карточек камер подвал с кнопками прижат к низу (`margin-top: auto`, при поддержке `subgrid` заголовок, текст и подвал соседних карточек лежат на общих линиях); список событий и плеер растянуты на общую высоту, список прокручивается внутри своей карточки (карточка размера `sm`, 20/16 px), пустой плеер заполняет карточку.
- **Заголовок страницы**: один `h1` на экран (Cormorant, `clamp(32px, 3.8vw, 44px)`), под ним сегодняшняя дата (`Intl`, часовой пояс из настроек) и бейдж состояния системы.
- **Состояния запуска**: статичный экран «Загрузка» (`role="status"`) на время `GET /auth`; при ошибке — экран «Не удалось связаться с Dozor» с кнопкой «Повторить» (`role="alert"`).
- **Опрос статуса** каждые 10 с только пока видна оболочка и вкладка браузера не скрыта, плюс обновление при возвращении на вкладку. После двух неудачных опросов подряд последний снимок остаётся, а бейдж показывает «Нет связи» и рядом время последних данных; тостов каждые 10 с нет.
- **Ошибки** (§10.8), сырой текст и коды не показываются: сеть → «Нет связи с Dozor. Проверьте сеть и повторите»; 401 (кроме входа) → экран входа с «Сессия истекла. Войдите снова»; 403 с CSRF → повторный `GET /auth`, при живой сессии запрос повторяется один раз с новым токеном, иначе экран входа с «Сессия устарела. Войдите снова»; 4xx с `{error}` → русский текст сервера с заглавной буквы; 5xx, не-JSON, неизвестное → «Не удалось выполнить действие. Повторите попытку». Серверный текст допускается, только если он содержит кириллицу и не содержит внутренних идентификаторов; из записей журнала убирается хвост `: <32 hex>`.
- **Уведомления**: область «Уведомления» с polite-живой зоной, кнопка «Закрыть уведомление», ошибки остаются до закрытия, остальные закрываются через 5 с (наведение и фокус ставят таймер на паузу). Ошибки действий из диалогов показываются внутри диалога (`role="alert"`): тосты лежат под затемнением.
- **Диалоги**: нативный `<dialog>` + `showModal()`, Escape, кнопка «Закрыть», ручной возврат фокуса инициатору (если его уже нет — на запасной элемент). Форма камеры не закрывается по клику на фон, чтобы не потерять введённое; закрыть её можно кнопкой «Закрыть», Escape или «Отмена» в подвале (на телефоне кнопка «Закрыть» уезжает вместе с прокруткой, а подвал стоит в конце формы). Кнопки «Получить ONVIF-профили» и «Проверить поток» лежат в теле формы рядом с их результатами, подвал содержит только «Отмена» и «Проверить и сохранить»; подтверждения (удаление камеры, выбор диска) закрываются и по фону. Подтверждение вместо `window.confirm`: последствия текстом, «Отмена» получает фокус.
- **Кнопки** во время запроса: `disabled` + `aria-busy`, подпись не меняется; фокус возвращается на кнопку, если браузер его сбросил.
- **Формы**: `novalidate` и собственные русские сообщения; ошибка — под полем, связана через `aria-describedby`, поле получает `aria-invalid`, фокус уходит на первое неверное. Пароль считается в символах (как раньше) и дополнительно в байтах (сервер ограничивает 72 байтами; кириллица — 2 байта на символ); так же проверяется название камеры (сервер ограничивает 100 байтами, в кириллице это 50 символов). Подписи без жаргона: «Адрес сервера S3» и «Адрес ONVIF» вместо «Endpoint».
- **Тело запросов** совместимо с сервером (`DisallowUnknownFields`): камера отправляет ровно `id, name, url, sub_url, onvif, username, password, motion, sensitivity, enabled, masks`; настройки — `timezone, s3{enabled, endpoint, region, bucket, prefix, access_key, secret_key, path_style, bytes_per_second}, auto_update, release_url`; вход — `password, token`; выбор диска — `uuid`. Заголовок `X-CSRF-Token` стоит на каждом запросе. `PUT /cameras/{id}` и `PUT /settings` отвечают новыми настройками (тот же `PublicConfig`, что и `GET /settings`), поэтому клиент берёт их из ответа: сбой повторного чтения после успешного сохранения не оставляет диалог в состоянии, из которого повтор создал бы вторую камеру. Проверка потока, ONVIF-профили и поиск при неожиданной ошибке сервера показывают действенный русский текст («Проверьте адрес, логин и пароль камеры»), а не общий.
- **Недоступный архив**: `GET /events` отвечает 503, пока архив не открыт (`disk_ready=false`), в том числе во время применения настроек. Если диск ещё не выбран, показывается предложение «Выбрать диск». При выбранном диске без ошибки — «Запуск записи…», при ошибке — «Архив недоступен» с причиной и ссылкой «Проверить настройки». Пустой список при `disk_ready=false`, общий баннер и статус системы используют то же объяснение.
- **Фокус в списке событий**: «Загрузить ещё» и «Повторить» перестраивают список, поэтому фокус, стоявший на кнопке, переходит на первую добавленную строку (или на новую кнопку «Повторить»), а не теряется на `body`.
- **Плеер и шкала времени**: логика прежняя — части без `deleted`, часы шкалы считаются с учётом разрывов (`gaps`), переход в разрыв и вне записи даёт предупреждение, конец части переключает на следующую. Исправлено: после простого клика по шкале без сдвига признак «перетаскивание» больше не залипает (сбрасывается на `pointerup`). При уходе с вкладки событий видео ставится на паузу.
- **Обновления**: кнопка «Проверить и обновить сейчас» вызывает `POST /updates/check` и работает при выключенном автообновлении. Использует сохранённый адрес выпуска; при изменённом поле просит сначала сохранить настройки. Кнопка заблокирована до завершения операции (`update_running`), рядом показаны проверка, скачивание, установка или результат. Подсказка предупреждает о краткой остановке записи, после перезапуска показывается предложение войти снова. `update_status` — текст сообщения `SystemUpdate`; клиент сопоставляет известные сообщения человекочитаемым («Установлена версия 1.4.2 · обновлено 4 октября 2026 г. в 06:12», «Установлена актуальная версия», «Не установлен ключ проверки подписи…» и др.), неизвестное заменяет нейтральной фразой. Известны также откат, несовпадение SHA256, сбой скачивания и конфликт хеша версии. Время берётся из RFC 3339 в сообщении об установке.
- **Выбранный диск**: раздел, который уже используется, помечен бейджем «Выбран» (статус словом), а не отключённой кнопкой: у disabled-кнопки с `opacity .5` подпись опускается ниже 4,5:1.
- **Русская типографика** (§5.5): неразрывные пробелы в HTML (`&nbsp;`) и в JS (функция `t()` ставит их после коротких предлогов и союзов, перед тире и внутри «число единица»; применяется к статическим строкам, подписям бейджей, заголовкам и описаниям пустых состояний и серверным сообщениям, но не к названиям камер); «ёлочки»; числа, проценты, байты (`Intl` unit, `ru-RU`, основание 1024 как раньше), даты и время — через `Intl` в настроенном часовом поясе; `Intl.PluralRules` для числа найденных камер; `tabular-nums` для чисел и времени.
- **Доступность**: ориентиры `header`/`nav`/`main` (в рейке от 1024 px вместо `nav` — `aside` с подписью «Разделы», так размечен компонент), один `h1`, `aria-labelledby` у секций, видимый фокус, подписи у всех полей, цели ≥ 44 px, `aria-current` у выбранного события, скрытая живая зона `#announce` для результатов загрузки и поиска, у прокручиваемого журнала своё имя («Последние сообщения»), у ползунка чувствительности `aria-valuetext` в процентах, у видео `aria-label`. Атрибут `datetime` у даты в шапке считается в настроенном часовом поясе, как и её текст. `prefers-reduced-motion`: без подъёмов, переходов и вращения спиннера, диалоги открываются сразу.

## Отступления от 00.md

- Тёмная тема (00 светлая) — утверждённое решение продукта; `AtmosphereHero`, сцены, морфинг экрана загрузки не используются, экран «Загрузка» статичный (как в запасном варианте без JS и при reduced motion).
- Меню — настоящий компонент 00, а не порт (раздел «Меню: общий компонент 00»); его поведение и разметка следуют пакету, а не 00.md.
- Форма камеры не закрывается по клику на фон; у подтверждений такого ограничения нет.
- Нативный `<select>` без кастомного списка; `<input type="date">` — браузерный календарь.
- Нет баннерного ориентира `header` на ширине ≥ 1024 px: бренд находится в навигации, `header` страницы лежит внутри `main`.
- Альфа тени paper увеличена для тёмной основы (см. выше).

## Как проверять вручную

Мок-сервера в репозитории нет. Проверка по ширинам 320, 375, 768, 1280 px (и на границе 1023/1024 px):

1. Вход и первый запуск (с кодом `setup-token`), неверный пароль и код, истёкшая сессия.
2. Обзор: карточка «Сводка» (камеры, шкала диска, очередь S3), список камер с четырьмя состояниями бейджа, журнал, пустые состояния, предупреждения о диске и ошибке выгрузки в S3.
3. События: без диска (сообщение и ссылка на настройки), фильтры, выбор строки, равная высота списка и плеера на ≥ 1024 px, возврат фокуса после «Загрузить ещё», «Загрузить ещё» (страница 200 записей), воспроизведение, шкала времени, разрыв, переход на следующую часть, скачивание, событие без частей.
4. Камеры: карточки одного ряда равны по высоте, кнопки на одной линии; поиск в сети (спиннер, пустой результат), добавление и настройка в диалоге, ошибки сервера внутри диалога, проверка потока, ONVIF-профили (на 320 px кнопки не выходят за строку), «Отмена» в конце формы на телефоне, удаление с подтверждением.
5. Настройки: список дисков (в том числе вложенные разделы и режим разработки), выбор диска с подтверждением, S3 и обновления, сообщения проверки полей.
6. Обрыв сети во время работы («Нет связи» без потока тостов), `prefers-reduced-motion`, навигация с клавиатуры.
7. Меню: активный пункт на каждом из пяти маршрутов и при неизвестном хэше, наведение и Tab раскрывают рейку, закрепление сдвигает страницу и сохраняется при переходах, «Выйти» в рейке, версия под названием, на 320 px все пять подписей нижней панели помещаются, тосты над нижней панелью.
8. `make check`, `go build ./...` и в консоли браузера нет нарушений CSP.
